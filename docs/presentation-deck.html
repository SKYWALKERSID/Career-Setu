Performance & Resilience

Dual-Layer Caching & AI Gateway

Zero repeated token costs, strict schema enforcement, and sub-second responses

12 / 18

Multi-Tier Caching Architecture

  • Tier 1: 15-Minute In-Memory TTL Cache
    Repeated calls return instantly (0ms latency, 0 tokens spent).
  • Tier 2: DB Input-Hash Prompt Cache
    Stores cryptographic hashes of profile inputs in ai_runs to avoid regenerating identical state.

Hybrid Failover AI Gateway

  • Primary: Groq (openai/gpt-oss-120b)
    Reasoning effort: medium with dynamic token cap < 8k TPM.
  • Fallback: Google Gemini (gemini-2.0-flash)
    15s timeout switch with Zod schema auto-repair.

Governance & Trust

Security, Privacy & Data Isolation

Enterprise-grade security controls safeguarding student identity and records

14 / 18

1. Strict PostgreSQL RLS

Every database query enforces Row-Level Security based on the authenticated Supabase user ID. Students can never access or modify another student's profile.

2. Ephemeral Resume Storage

Resumes are saved in private buckets with time-limited signed access tokens. Raw documents are never shared publicly or exposed to third parties.

3. Zero Secret Leakage

AI provider keys (GROQ_API_KEY, GEMINI_API_KEY, Service Role keys) run exclusively on server runtimes and never leak into client bundles.

4. Algorithmic Fairness

Scoring models completely exclude demographic, gender, caste, and religious attributes, ensuring 100% merit- and skill-based evaluation.
